# ZITRO Super Admin — Manual / Real-Time Test Scenarios

> **Purpose:** a human-executable QA checklist for `zitro-superadmin`, run against a live
> dev/staging server — not the automated Vitest/Playwright suite (that's `SA-TEST-001`/`002`,
> still `[ ]`). Several scenarios below specifically verify **real-time propagation**: a
> change made in this app should be visible in the _other_ live apps (`zitro-customer`,
> `zitro-restaurant`, `zitro-admin`) without a redeploy — that's the whole point of TASK-036.
> This document can also seed `SA-TEST-002`'s E2E specs later.
>
> **Status reference:** `SUPERADMIN-STATUS.md` — SA-000 through SA-006 are `[x]` done;
> SA-007 (extended analytics) and SA-008 (Firebase Hosting deploy) are `[ ]`, see §7.

---

## 0. Before you start

**Environment**

- [ ] `zitro-api` running locally or against staging, with the TASK-036 schema applied
      (`app_translations`, `app_feature_flags`, `app_ui_configs`, `app_themes`,
      `user_language_preferences` — see `zitro-api/docs/schema/ZITRO-Production-Schema.sql`,
      marked `NOT YET APPLIED` until you run it).
- [ ] `nx serve zitro-superadmin` running.
- [ ] For the real-time propagation scenarios (§3, §5): also run `nx serve zitro-customer`
      (or `zitro-restaurant`/`zitro-admin`) in a second tab, since those are the "target apps."

**Test accounts needed**

- [ ] One Admin JWT account with role `SuperAdmin` (full access — this is the primary
      account for this whole document).
- [ ] One Admin JWT account with a non-SuperAdmin role (`Ops`, `Support`, or `Finance`) —
      used only in §8.1 to verify permission boundaries.
- [ ] One customer-app account (any phone-verified user) — used only in §3.4/§5.4 to verify
      propagation to a real end-user surface.

**Conventions used below**

- `[data-testid="..."]` — query the element by this attribute in dev tools or Playwright.
- Where no `data-testid` exists, the scenario says so and gives the `id`/label to use instead
  — don't assume a missing testid is your mistake, it's a real gap, see §7.3.
- **Cache TTL to remember:** `GET /api/app-config` is `Cache-Control: max-age=3600` (1 hour),
  `GET /api/translations` is 24 hours. A propagation scenario that "doesn't show up
  immediately" on the target app may just be a warm HTTP cache — hard-refresh
  (bypass cache) before concluding something is broken.
